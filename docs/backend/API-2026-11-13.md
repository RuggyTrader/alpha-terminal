**Labelled TEST fixture, not live performance.** Values above come from `worker/test/backend_accounting.test.mjs`: 5,002 alternating legacy trades plus one bot trade. The real object also includes win rate, profit factor, expectancy, first/last close timestamps.

Use `lifetime` for whole-account headline metrics. It includes all closed ALPHA PAPER legacy trades plus bot-ledger closed positions, without a row limit. It excludes Mirror, open trades and internal transfers. Historical decimal legacy amounts are rounded to micro-USD once per trade, without rewriting history. Bot amounts remain authoritative integer micro-USD. Drawdown is calculated by close time, with deterministic ledger/id ordering for ties; it is not intratrade drawdown.

The existing `trades` array remains the legacy list capped at 5,000. Do not infer its scope matches the new aggregate or combine its P&L with the aggregate. Per-bot lifetime metrics already exist at `/api/dashboard/bots`; the new lifetime object above is account-wide. The internal aggregate helper's bot filter is not a new public route.

Schema 6 returns legacy lifetime performance without requiring bot tables. No endpoint removed, no auth changes, no migration.

## Account equity and unpaid liabilities

The existing dashboard portfolio section adds these fields per wallet and in totals:

| Field | Meaning |
|---|---|
| `shortfall_usd` | Recorded unpaid liability; never automatically funded from MAIN |
| `economic_net_realized_pnl_usd` | Wallet paid realized P&L − fees − unpaid shortfall |
| `equity_usd` | Cash + reserved cost/collateral + last recorded unrealized P&L − shortfall |

`book_balance_usd` retains its cash-plus-reserved meaning. `net_realized_pnl_usd` retains the historical wallet-paid accounting meaning. The new economic field includes the portion a wallet could not pay. Internal transfers do not affect total funding or equity. A profit sweep is already included in trading P&L; never add it again.

Bot LONG and SHORT positions now contribute to unrealized P&L. SHORT UPL is `(entry − mark) × quantity`; proceeds remain restricted and are never added as spendable cash. Dashboard mark refresh now updates open bot positions through the existing throttled Kraken request. A failed quote keeps the prior price **and its timestamp**. These values are based on last recorded marks, not a guarantee of a current executable price. Keep the stale/fresh presentation tied to recorded mark timestamps. Missing marks return null equity/UPL instead of zero. Calculation precision is micro-USD; round only for display.

TEST example: a $1,000 account with a 0.5 SOL short at $80, $0.08 entry fee and a $90 mark has −$5 UPL and $994.92 equity. No short-sale proceeds are counted as cash.

## Order and owner-action outcomes

| Addition | Behavior |
|---|---|
| `BOT_PROFILE_MISMATCH` | Reject new entry when a supplied `config_hash` differs from the registered original profile |
| `BOT_SHORTFALL` | Reject new entry or resume request with unpaid shortfall, including after another allocation |
| `data.reduced_to_risk` | Entry quantity was reduced at the actual reference price to respect stop risk |
| `data.risk_usd` | Lesser of bot approved risk and valid requested risk, used by this entry |

Existing `reduced_to_fit` continues to mean reduction to available capital. `qty` is the filled quantity; `requested_qty` retains the request. Store/display the filled quantity for actual P&L. For a TEST request of 0.5 SOL at $80 with a $60 stop and $2 risk, the filled quantity is 0.1 SOL. Stop-risk checking requires a finite positive recorded stop; older callers omitting a stop retain compatibility. Fees and price gaps can make actual losses exceed planned stop risk.

Hash omission remains accepted for compatibility; the real fleet engine supplies it. CLOSE remains possible when a supplied hash is old, so a metadata mismatch does not trap an open position. No original profile or signal rule changed.

The existing `CONCURRENT_ORDER` 409 now also covers a change in account exposure, available position slots or bot entry permissions between precheck and transaction. Nothing is committed; retry with the same order id. The next precheck can return the applicable durable refusal. Bot order outcomes requested from `/webhook/bot-ledger` are now scoped to that bot.

Settlement returns the committed shortfall rather than a pre-transaction estimate. Profit settlement, both sweep legs and fee records remain one atomic D1 batch. The default Worker test command bounds test-file concurrency to two; it does not remove tests or raise timeouts.

## Execution model to preserve in the UI

Funded PAPER is a reference-price execution model: the engine resolves candle-based strategy orders, then the Worker records a fill at the Kraken ticker when the message arrives. It is not an exchange resting-limit order book. Pending entries are engine state, not reserved D1 orders. Do not label the Worker price as a guaranteed limit fill, maker fill, or the Mirror's exact hypothetical price. Full exchange-style pending-order reservation/limit enforcement needs a coordinated execution contract before implementation.

No research configuration is enabled. Research model output is never a funded balance or account performance metric.
